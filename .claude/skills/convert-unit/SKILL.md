# 단원 콘텐츠 변환 + 선생님 검토

목표는 **학습**이다. 교재 원문은 빠짐없이 그대로 옮기고(원본 충실성), 그 위에 학습을 돕는 보강을 **AI 표시와 함께** 더한다.
교재 원문과 AI 생성물을 절대 섞지 않는다. 확신이 없으면 지어내지 말고 `review.fixes`에 "확인 필요"로 남긴다.

## 0. 준비

- 교재: `일본어문법무작정따라하기.pdf` (bookId `5ab70b9f895f305a`, PDF 쪽 = 인쇄 쪽)
- 단원 목록·쪽 범위: `books/5ab70b9f895f305a.zip`의 `manifest.json` → `chapters` (id 예: `c-3-1-2`, startPage~endPage)
  ```bash
  python -I -c "import zipfile,json;m=json.loads(zipfile.ZipFile('books/5ab70b9f895f305a.zip').read('manifest.json'));[print(c['id'],c['startPage'],c['endPage'],c['title']) for c in m['chapters']]"
  ```
  (Windows 콘솔에서 한글이 깨지면 `PYTHONIOENCODING=utf-8`)
- 단원 범위 끝에 다음 마디/마당 표지 쪽이 포함될 수 있다(표지는 변환하지 않음).
- 정답: 특별부록 01 "맛보기 연습 및 실력 다지기 정답" (p.582~661). 단원 순서대로 있다. 해당 단원 부분을 찾아 읽는다.
- **정답 스캔 누락**: 합본 PDF는 p.582~603까지만 정답이 있고 p.604~668은 빈 페이지다.
  p.661(마지막 정답 쪽)과 p.662~668(문형 찾아보기)은 `../일본어문법무작정따라하기/13022026203629-0001.pdf`(1쪽=p.661)와 `13022026203721-0001.pdf`에 있다.
  **p.604~660 정답은 어디에도 없다.** 이 범위 단원의 맛보기·실력 다지기는 선생님이 정답을 작성해 `answers`에 넣고 `"answerBy": "teacher"`를 붙인다.
  자연스러운 다른 답은 평소처럼 `alts`로. review.fixes에 "부록 정답 스캔 누락(p.604~660) — 연습 문제 N개 선생님 작성 정답"을 한 줄로 남긴다.
  본문 예문(`src: example`)은 본문에 원문이 있으니 해당 없음.
- 출력: `books/5ab70b9f895f305a/content/<chapterId>.json` (Git 제외 폴더 — 교재 저작물)
- 형식 정의: `src/content.ts` / 완성 예시: `books/5ab70b9f895f305a/content/c-3-1-1.json` (먼저 읽고 똑같은 스타일로)

## 1. 원문 판독

```bash
python -I tools/render_pages.py 일본어문법무작정따라하기.pdf <첫쪽> <끝쪽> <scratchpad>/<chapterId>
python -I tools/render_pages.py 일본어문법무작정따라하기.pdf <정답쪽> <정답쪽> <scratchpad>/<chapterId> [--top 0.5]
```
렌더링한 PNG를 Read로 **한 쪽씩 전부** 읽는다. 작은 글씨(왼쪽 여백 단어, ≫ 해설)도 빠뜨리지 않는다.
PDF 처리 중 나오는 `MuPDF error: format error: non-page object in page tree`는 무시해도 된다.

## 2. JSON 작성 규칙

- `cards`: 원문 **순서 그대로**. 문형(①②…)마다 `grammar` 카드 1장, 그 뒤 `맛보기 연습`은 `practice` 카드, 포인트 정리 `summary`, 실력 다지기 `drill`, 장문 도전하기 `reading`, 잠깐만요·덤 챙겨 가세요 `tip`.
  - 설명 문장은 요약하지 말고 그대로. ≫ 해설은 `note` 블록. 공식 박스는 `formula`. 예문은 `ex`(목표 문법 부분은 `hl`).
  - 연습 문제는 카드 안에 `{ "t": "q", "ref": "<sentence id>" }`로 참조만 하고 실제 문제·정답은 `sentences`에.
- `grammar`: 문형 번호·형태·뜻·쪽.
- `sentences` (3단계 예문 작성 문제):
  - `src`: `example`(본문 예문, 한국어→일본어) / `practice`(맛보기, `given`=주어진 단어) / `drill`(실력 다지기)
  - `answers`: **교재(부록 정답)에 실린 답만**. 부록에 "/"로 나열된 것은 모두 넣는다.
  - `alts`: 선생님 판단으로 자연스럽고 문법 목표에도 맞는 다른 답 (예: 私→僕/俺, じゃない↔ではない). 목표 문법을 벗어나는 답은 넣지 않는다.
  - `kana`: answers·alts 각각의 **가나 읽기** (한자 → 히라가나, 가타카나 단어는 그대로, 문장부호 유지). 폰에서 가나로 입력해도 정답 처리하기 위함. 모든 sentence에 필수.
  - `hint`: 교재 문제에 붙은 ≫ 안내문.
- `vocab`: `origin`으로 출처 구분
  - `list`: 왼쪽 여백 단어 목록 + 장문의 {단어} 목록 (단원 안 중복은 첫 등장만)
  - `text`: 목록엔 없지만 본문·해설·예문에 나와 학습에 필요한 단어 (뜻이 교재 문장에서 확인되는 것)
  - `ai`: 교재에 없지만 함께 익히면 좋은 단어 2~4개, `why`에 이유. (사용자 승인 대상)
  - 읽기는 히라가나(가타카나 단어는 그대로). 뜻은 교재 표기 그대로 (높임×) 같은 표시 유지.
- `audio`: 페이지에 표시된 mp3 이름과 위치.

## 2-1. 긴 단원은 하루 분량으로 나누기 (`parts`)

평균 단원 = 약 7쪽 · 문형 4~5개 · 예문 문제 약 40개 (하루 루틴 1회 분량).
**10쪽을 넘거나 문형이 6개를 넘는 단원**은 문형 경계에서 2~4개 part로 나눈다. 짧은 단원은 parts를 넣지 않는다.
```json
"parts": [
  { "id": "p1", "title": "(1) 문형 ①~③", "cards": ["k01", "k02", "k03", "k04", "k05", "k06", "k07"] },
  { "id": "p2", "title": "(2) 문형 ④~⑥ · 정리", "cards": ["k08", "...", "k20"] }
]
```
- 문형 카드와 그 문형의 맛보기 연습은 같은 part에. 포인트 정리·실력 다지기·장문·팁·선생님 정리는 마지막 part에.
- 모든 카드가 정확히 한 part에 들어가야 한다 (검증 테스트가 확인). title은 `(1) …`, `(2) …`처럼 번호 + 다루는 문형.

## 3. 선생님 보강 (AI 표시 필수)

**말투**: 학생 옆에서 설명해 주는 **친절하고 다정한 선생님**처럼. 존댓말 '~해요' 체, 따뜻하게 격려하고, 짧고 쉽게.
기계적인 요약체("~임", "~할 것", "주의:")나 딱딱한 설명은 쓰지 않는다. 출처 구분은 앱이 'AI' 태그로 해 주므로 본문에 "AI가"라고 쓰지 않는다.
- 좋은 예: "많이들 하는 실수 하나 알려 줄게요. ~에 끌려서 ~라고 쓰기 쉬운데요, ~하면 끝이에요!"
- 좋은 예: "오늘 정말 수고 많았어요! ~만 기억하면 돼요."
- 나쁜 예: "주의: 명사 뒤 が 삽입 금지." / "핵심 요약: ~"
- AI 제안 단어의 `why`도 같은 말투로 ("~랑 같이 외워 두면 ~가 한 번에 정리돼요.").

- 각 `grammar` 카드 마지막에 `{ "t": "teacher", "text": "..." }` 1~2개: 한국어 화자가 자주 하는 실수, 헷갈리는 비교, 외우는 요령. 짧고 정확하게.
- 단원 끝에 `kind: "teacher"` 카드 1장 "선생님 정리": 이 단원 핵심을 3~5줄로 + 앞 단원과의 연결.
- 본문 예문 `ex` 블록에 `kana`(읽기)를 붙인다.
- 교재 원문 블록(`p`, `note`, `ex`의 ja/ko 등)은 고치지 않는다. 교재 오탈자로 보이는 것은 원문 그대로 두고 `review.fixes`에 적는다.

## 3-1. 가나 읽기 채우기

```bash
python -I tools/add_kana.py books/5ab70b9f895f305a/content/<chapterId>.json
```
- vocab 읽기로 예문·정답·`ex` 블록의 `kana`를 채운다 (이미 있는 kana는 유지).
- 한자가 남으면 실패 → 그 단어를 vocab(`text`)에 넣거나, 문맥상 읽기가 다른 표현은 JSON 최상위 `"kanaHints": {"一人": "ひとり"}`에 추가하고 다시 실행.
- 결과 `<파일>.kana.txt`를 **Read로 전부 확인**한다 (人·日·方·生처럼 문맥 따라 읽기가 바뀌는 한자 주의).
- 콘솔(cp949)에서 일본어 출력이 깨지므로 결과 확인은 반드시 파일로 한다.

## 4. 선생님 검토 (스스로 반드시)

작성 후 원본 PNG와 한 번 더 대조하며 점검:
1. 원문 누락: 모든 설명·예문·해설·연습·표가 카드에 있는가
2. 일본어 판독: 탁음/반탁음(は·ば·ぱ), 촉음(っ), 장음(ー), 작은 글자(ゃゅょ), 비슷한 한자 오독
3. 정답: 부록과 일치, alts가 목표 문법에 맞는가, kana가 answers와 1:1로 맞는가
4. 단어 읽기·뜻 정확성
결과를 `"review": { "by": "ai-teacher", "at": "YYYY-MM-DD", "fixes": ["검토 중 고친 것 / 확인 필요 항목"] }`로 기록 (고친 게 없으면 `"원문 대조 이상 없음"`).

```bash
npm test
```
`content.test.ts`가 `books/*/content/*.json`을 전부 검증한다 (참조 오류, 가나 읽기 누락·한자 혼입, review 누락). 실패하면 고친다.

## 6. 특수 단원

- 준비마당(히라가나·가타카나·한자 소개): `cards`는 원문 설명·표 그대로, `vocab`에 각 글자(ja=글자, reading=글자, ko=한글 발음)를 `list`로. 예문 작성 문제가 없으면 `sentences: []`, `grammar: []`.
- 특별 부록(정답·문형 찾아보기), 앞부분: 변환하지 않는다.
